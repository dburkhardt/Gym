# BioAgent Bench: maintained native executor

This adapter executes the pinned creator Verifiers 0.2/OpenCode 1.15.11 workflow; it does not merely import an old trace. Historical trace import is preserved separately at `responses_api_agents/bioagent_native/importer.py`. The native Gym dataset retains all ten frozen workflows, including large-data and GIAB cases. A source-ready plan is not Docker or scientific acceptance.

The native taskset, prompts, setup, finalize, deterministic scorer and pipeline judge remain creator code. Solver sampling remains temperature 0.2, high reasoning, 32768 output tokens; judge medium reasoning. Both roles use the configured campaign Nemotron model. Creator phase limits remain 3600/14400/3600/3600 seconds. Native `results_match` is the reward; judge assessment metrics remain separate. A clean creator-scored model budget outcome retains its native reward, including zero. Scoring/provider/runtime errors remain attempted but unscored; even a partial reward is not accepted unless native scoring finished without errors. Raw rewards and errors remain available, and no missing score becomes zero.

Set `BIOAGENT_METADATA`, `BIOAGENT_CREATOR_ROOT`, `BIOAGENT_NATIVE_PYTHON`, `BIOAGENT_ASSET_ROOT`, `BIOAGENT_ASSET_MANIFEST`, `BIOAGENT_IMAGE` and `BIOAGENT_OUTPUT_ROOT`; use `gym eval plan --config benchmarks/bioagentbench/config.yaml`. The asset manifest format is `{"tasks":{"task-id":{"files":{"data/file":"sha256", "reference/file":"sha256", "results/file":"sha256"}}}}`. Every actual file in the selected task's three trees must match, with symlinks rejected. The immutable image and selected interpreter must already be qualified; missing scientific tools are failures, not omitted metrics.

Prepared public inputs are copied through shared atomic staging to a fresh owned directory. This retains writable input/reference behavior (for scientific indexes) without changing the preserved originals. Full-copy disk headroom must leave 8 GiB free; a blocked large workflow is not replaced by a smaller one. The native `local` staging method points at these exact copied assets, instead of re-downloading them. The selected packet and source/import identities are recorded. Distribution bytes and packages subsequently downloaded by the creator are not claimed hermetically pinned.

The native Runtime interface uses shared owned Docker lifecycle, 2 CPU/8 GiB limits, bridge networking and a TTL. No host network namespace is used. Scientific outbound networking remains available. Only task-owned public data/reference and workspace are mounted; truth results and creator scoring code stay in the trusted host controller. This is not a claim of a deny-all-host-services network policy: real worker network tests remain an admission gate.

OpenCode reaches only the creator's per-rollout authenticated interception route through a task-owned Unix socket relay. The native model client and judge are adapted to Gym's aiohttp transport with durable request and actual streaming-chunk records. A malformed or interrupted body poisons the transport; SDK retries cannot dispatch a new call. No provider credentials enter the solver. The Gym parent snapshots only the pinned creator Git tree into fresh owned state, excluding all ignored/untracked checkout files and refusing archive symlinks; the separate creator process verifies pinned creator/Verifiers sources and actual imports before dispatch. Asset manifests reject absolute paths, parent traversal and unexpected categories before publication. Fresh output claims prevent implicit repeat execution; automatic native `--resume` and whole-rollout retries are disabled.

Offline tests cover native configuration construction, ownership/cancellation contracts, timeout error classification, exact writable input copies, disk refusal, real Unix-socket authentication/path/stream behavior, and interrupted-stream refusal. They do not certify a real Docker runtime, full native OpenCode execution, all scientific dependencies, or live model results. Before admission, run a complete native fake-provider task in the actual immutable image, inspect real mounts/network/limits/cleanup, verify creator scorer parity and current worker budget/capacity, then separately admit live inference. Historical attempts and unresolved calls must remain separate.

`qualify_runtime.py` is a prepared full native no-output control using a local deterministic provider and unchanged 8 GiB runtime. It has not passed an actual Docker/OpenCode run. `Runtime.Dockerfile` requires a qualified immutable Python 3.13 base and checksum-pinned OpenCode 1.15.11 archive; no concrete unverified digest is supplied.

The controller and creator require separate environments. `BIOAGENT_NATIVE_PYTHON` selects the exact creator Python 3.13 environment with its unchanged `uv.lock`; the native agent launches its parent worker using the current Gym interpreter. Qualification records both interpreters and actual imports. The child must not import Gym. This preserves creator OpenAI/Verifiers versions without installing them over Gym networking dependencies or waiving Gym dependency floors. It does not independently certify the creator dependencies' security properties.

The parent owns one fixed sandbox, references, guarded model transport and an absolute operation deadline. The six creator Runtime methods cross a private authenticated Unix socket with contiguous operation ordinals and intent/completion records. Unknown methods, repeated ordinals, expired deadlines and disconnected operations fail closed; a completed operation whose reply is lost is never automatically repeated. Parent teardown settles active operations and preserves the original error if cleanup also fails. Private runtime/model sockets and the ephemeral IPC token packet are not mounted in the solver container; only its existing interception relay directory is mounted. This is a fresh-run boundary, not checkpoint continuation.
