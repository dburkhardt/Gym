# ChemX two-article image baseline

This is a newly frozen sample, `chemx-magnetic-two-article-image-v1`, not a recovered historical five-task pilot. It contains two creator-listed articles and 22 reference rows: `d0na00820f.pdf` (four rows) and `nano12183159.pdf` (18 rows). Input PDFs and creator source files are pinned in `frozen.json`. Article and reference-row counts must not be conflated.

Preparation uses the creator image baseline: original magnetic system/instruction prompts and strict JSON schema, the article followed by its supplementary PDF, Poppler rendering at 500 DPI, and a 10,000-output-token cap. Explicit page-number order removes the upstream script's unspecified filesystem ordering; record this operational choice when comparing runs. No page is omitted or downsampled. The OpenAI Assistants/file-search PDF baseline is a different protocol and is not implemented here. Any benchmark inference must use the campaign-authorized Nemotron model, including any subsequently added LLM roles; there is no LLM judge in this adapter.

Set `CHEMX_SOURCE` to the pinned creator checkout, `CHEMX_ASSETS` to the acquired PDF directory, and `CHEMX_PREPARED_DIR` to a task-owned output directory. Install `requirements-prepare.txt` in the preparation environment and Poppler separately (the creator does not pin Poppler). Preparation admits at most 60 million pixels per page and 64 MiB of base64 image bytes per article; it fails rather than changing the protocol. Rendering is one page at a time. Native planning can reuse the prepared file with `use_cached_prepared_benchmarks: true`.

The local qualification rendered 22 and 14 pages respectively, using Poppler 26.09.0, pypdf 5.5.0, pdf2image 1.17.0 and Pillow 11.2.1. Raw JPEG totals are about 38.4 and 26.9 MB; inline request size, supported image count and vision context capacity are **not provider-qualified**. Native planning is not inference admission.

The verifier uses the exact pinned creator `convert_comma` and `calc_metrics` functions, loading only their AST definitions to avoid import-time dataset/network dependencies. It preserves predicted-row deduplication, numeric normalization of reference columns, and per-column multiset matching. Reference records are frozen from the creator repository's `datasets/Nanomag.csv`, rather than an unversioned live Hugging Face download; equivalence to every historical HF release is not claimed. The scalar reward is an explicitly named mean of creator column F1 values, not a published suite score. All per-column counts/precision/recall/F1 remain in `scoring_details`. Column multisets can score a row-association error as correct; a regression preserves and exposes this limitation.

Malformed/empty non-JSON model output has no creator score: it returns a masked placeholder with `raw_reward: null` and an explicit model-output or output-budget disposition. Valid JSON with an empty samples array scores zero under the creator calculation. Source/hash/scorer failures still raise as infrastructure failures. Reverification preserves preexisting transport/model failures and masks; it does not erase historical failures.
