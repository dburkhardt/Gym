## Separate grouped creator-library report

`grouped_report.py` operates on saved native rows without modifying rewards or invoking docking/inference. It verifies SHA256 hashes of the three metric modules and notebook extraction source from commit `f033a3dfea50c3be5782a979e73eeeb842a7bae1`, then executes the original metric functions. Install the separate `requirements-report.txt` environment if needed; each result records RDKit/NumPy/SciPy versions, which can affect fingerprints and tie ordering.

```sh
python -m benchmarks.molrgen.grouped_report --rows saved.jsonl --scope scope.json --source /absolute/path/MolRGen --output grouped.json
```

The explicit scope JSON contains `expected_draws` (prompt ID to draw count, each at least2), `k`, `similarity_threshold`, and `fingerprint`. Counts refer to the requested analysis scope, not evidence of dispatched calls. Each accepted group requires exactly that many distinct native rollout indices, identical prompts/model/generation settings/reward metadata/oracle conditions, usable creator scores, and receipts matching the actual saved completion. Incomplete groups remain unscored with raw values and observed counts preserved. Regrades or retries are not independent scientific draws. A missing verifier score is not a model-error zero. A valid creator zero after model budget exhaustion remains part of its draw group.

The original library `top_k` canonicalizes SMILES, retains the **first** duplicate's score, pads missing unique slots with zeros, then selects the highest k. The diversity function does not first canonical-deduplicate: it sorts weights using NumPy, greedily accepts fingerprints at distance at least `1 - similarity_threshold` from selected molecules (equality is allowed), and pads the unfilled k slots with zeros. The default library fingerprint is ECFP4-1024, but this report requires it explicitly. Extraction follows the creator notebook's last-SMILES convention: multiple extracted molecules use the final molecular reward, while no extracted molecule remains an empty-molecule zero draw. Raw completion rewards are retained separately from these selected molecular rewards.

These library metrics are **not automatically the published analysis protocol**. The notebook's analysis uses ECFP4-2048, rollout scopes15/50/100 and top-k curves up to30; its ordinary top-k helper sorts before deduplication and randomly samples draws. Those choices differ from the library's first-duplicate behavior. Reports therefore always mark `published_sampling_reproduced: false`. Reproducing published results additionally requires the exact prompt cohort, generation/oracle protocol, draw selection/order/randomness and notebook aggregation recipe; selecting k or a fingerprint alone does not establish that.

The preserved native five-output cohort contains five distinct prompts with one draw each. Saved-output qualification preserved all five original rewards (including zeros), verified creator receipt extraction, and refused every grouped sampling result. No top-k/diversity figure was fabricated from that singleton-per-prompt cohort. Semantic controls cover canonical duplicate ordering, zero padding, the creator's exact diversity fixture, valid budget-zero inclusion, incomplete/masked groups, altered receipts and dirty source refusal. No new model or oracle calls were made for these controls.

The CLI creates its output exclusively and refuses overwriting a historical report. Every group retains each draw's identity, raw reward, mask, failure reason and response status, including undersampled groups. Only an explicitly identified `max_output_tokens` incomplete response can participate as a model-budget outcome when its creator score is valid; content-filtered or unexplained incomplete responses remain unresolved.
