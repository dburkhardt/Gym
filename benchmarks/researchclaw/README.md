# ResearchClaw calibration staging

This integration freezes Neuroscience_000 (SimBA behavior classification) and Life_002 (protein structural alignment), preserving the creator instruction template, declared inputs and related literature. It does not claim coverage of all40 mixed-domain tasks. The generated manifest lists every remaining task explicitly; eligibility of those remaining tasks requires individual review.

Run `python benchmarks/researchclaw/prepare.py SOURCE OUTPUT` once into a new directory. `environment/workspace` contains only declared public data, related_work and native instructions. `judge-only` contains the target study/checklists and must never enter the solver image or mount namespace. Neuroscience_000's machine_results_reference.csv is deliberately retained: the creator explicitly supplies this as public contextual input. Public reference material is therefore not synonymous with hidden grading data.

The two tasks are a CPU/no-network campaign variant, bounded2CPU/4GiB/7200s; this is not the paper's complete agent protocol. The current files are staging, not a launch-ready integration. No inference has run. Before execution: build a scientific tools image, verify all source hashes and imports, prove actual solver reference denial, configure Gym Harbor with exact Super and preserve full tool/model receipts, and implement artifact capture plus host-side native evaluation. No fake zero reward should substitute for pending grading.

`native_score.py SOURCE WORKSPACE OUTPUT.json` calls the creator's score_workspace unchanged. Set JUDGE_MODEL_NAME to nvidia/nvidia/nemotron-3.5-super-vl and JUDGE_API_BASE/JUDGE_API_KEY to the isolated audited transport. Raw provider requests/responses must be captured by that transport; parsed call receipts here are additional evidence, not a substitute. The creator uses500 output tokens,120s and max_try2; preserve this protocol and report incomplete attempts before considering an explicitly labeled larger-budget variant. Its weighted0–100 checklist score is retained under native; normalized reward is null when parsed responses are invalid or native evaluation errors. Native parsed zero remains a genuine score. Scores compare report/checklist agreement, not independently certified scientific correctness.

Controls: `python benchmarks/researchclaw/test_controls.py` checks genuine zero versus malformed judge output, missing report and component preservation. These four tests do not certify live native judge operation or sandbox isolation.

Harbor wiring is staged in `campaign.yaml`. Build the declared tools image as `researchclaw-tools:campaign`, then materialize with prepare.py. Set SCIENTIFIC_HARBOR_TASKS_DIR to a directory containing only the two task folders (keep judge-only and manifest outside that dataset directory); set SCIENTIFIC_HARBOR_JOBS_DIR, POLICY_BASE_URL and POLICY_API_KEY. Capture verifier emits only the named operational `artifact_capture_complete` metric and `grading-status.json` with scientific_score=null. Do not import this operational metric as benchmark reward. Run native_score.py against captured workspace after completion, outside solver namespace. The scientific result is only that sidecar's preserved native checklist score, with failed judges masked.

Native mock control: set RESEARCHCLAW_SOURCE to the pinned checkout and run test_native_mock.py with Python3.10+. It imports actual creator score_workspace and substitutes only structai's call boundary, exercising all five Life_002 criteria, native valid50/invalid0 behavior and exact model/budget settings without network calls. This validates native integration but not the real structai client's raw transport handling. Live infrastructure, dependency/image build, dropped-UID isolation and response receipts remain required gates.
