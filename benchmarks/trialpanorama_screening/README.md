# TrialPanorama study-screening branch

This is only the creator's batched study-screening task, not all eight TrialPanorama tasks. Source https://github.com/RyanWangZf/TrialPanorama at `20e97cbb823003fccc425732d593cf2bb205d163`; test data https://huggingface.co/datasets/zifeng-ai/TrialPanorama-benchmark at `fb4c995efd5c3d64e66c7ffb73ebdbcc9d807987`. The newer TrialPanorama/Dataset release contains SFT parquet files and is not substituted for this test split.

The 100 test records comprise 979 individual study decisions. Each prompt retains its entire review setup and batch of 6–10 study titles/abstracts; references remain in verifier metadata. No conversion to independent yes/no questions occurs. Nested seed-20261020 5/20/50 samples are saved separately. Missing original title/abstract fields are preserved and identified by PMID, not fabricated or silently dropped.

Four creator methods are AST-isolated from the pinned task class: system prompt, input formatting, response parsing and scoring. Raw micro accuracy is the scalar Gym reward; all per-study evaluations and creator macro accuracy are retained. The creator parser defaults malformed answers to all-excluded, and its accuracy ignores omitted PMIDs. Therefore empty output can earn partial credit and a selectively incomplete answer can earn 1. These defects are preserved as raw metrics, with strict JSON/complete-PMID diagnostics. Do not interpret raw score alone as reliable performance. Per-study aggregate metrics must use retained evaluations and report invalid/missing answers separately. Mean batch accuracy is not identical to population-weighted accuracy.

Configure `creator_root` under `trialpanorama_screening.resources_servers.trialpanorama_screening`; set `CAMPAIGN_SAMPLE_JSONL`, then run `python benchmarks/trialpanorama_screening/prepare.py`. Intended native entry point is `gym eval run --benchmark trialpanorama_screening`. Standard Gym dependencies suffice. Three tests pass including right/wrong/empty, omitted-answer inflation, and full native Config plus actual HTTP verifier. A live five-batch rollout completed (44/50 creator label slots correct). One source PMID is duplicated and counted twice; five missing-context PMID occurrences appear across four batches. The strict unique-PMID flag distinguishes the duplicate batch, but source-induced duplicates must not automatically be blamed on model behavior. Verified remains false pending independent semantic review. Search, evidence summaries and the five design tasks remain unimplemented and are not credited as covered.

## Saved-output aggregate reporting

`resources_servers.trialpanorama_screening.reporting.aggregate_saved` checks exact frozen input/reference coverage and replays the pinned creator before aggregation. It reports **creator mean batch-micro** and **creator mean all-correct macro** separately, following `study_screening.py` lines305–312. The prediction-weighted fraction across all study decisions is a different metric. Raw metrics retain source defects and parser fallback behavior.

The explicit complete-output variant scores malformed/incomplete model answers zero, but leaves duplicate-reference batches unresolved rather than assigning model failure. Its denominator and unresolved task IDs are always reported; it must not replace the full-population creator means silently. No historical result is modified.
