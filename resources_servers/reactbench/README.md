# ReactBench released-prompt pilot

Source: https://huggingface.co/datasets/IDEA-AI4S/ReactBench at `d5ad4de2915106e9cf9fe71d795fce0d0128c797`; paper https://arxiv.org/abs/2604.15994. The `train` split is the released benchmark, not a separate training corpus. It contains 1,618 image/question/answer records. Original image bytes and inline response instructions are preserved, with no additional system prompt. References remain only in verifier metadata.

The paper describes extracting a short answer with prompting/template matching and exact string comparison. No evaluation scripts or extraction template are present in the released files. Consequently this adapter is explicitly a conservative **released inline prompt + outer-whitespace-trim exact-match variant**, not an exact reproduction of the published extraction pipeline. The diagnostic also records literal byte equality. Numeric words, explanations and alternative units are not silently normalized. An exact-match miss cannot automatically be interpreted as scientific failure; retain full responses for audit. The paper's optional Gemini semantic-judge analysis is not implemented.

The four topology categories are graph (120), multiple (490), single (425), and tree (583). These are not the paper's localization/extraction/tracing/reasoning task categories, which are not released as a row field. Samples are topology-stratified with seed 20261020, nested 5/20/50. All 1,618 images decode successfully and every question/answer is nonempty. Shared images mean question-level samples are correlated; do not treat 20 questions as 20 independent diagrams.

Set `CAMPAIGN_SAMPLE_JSONL` to a prepared sample and execute `python benchmarks/reactbench/prepare.py`. Native intended entry point is `gym eval run --benchmark reactbench`. Full Config and HTTP `/verify` tests pass; a live image rollout has not been run by this agent. Standard Gym runtime dependencies suffice for scoring; sample preparation additionally uses PyArrow and Pillow. Raw data are not committed.
