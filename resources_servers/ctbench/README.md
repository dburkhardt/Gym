The adapter executes the pinned creator zero-shot prompt, backtick feature extraction, semantic-matching judge prompt, and precision/recall/F1 arithmetic. Model generation should use temperature 0, seed 42, max output 1,000 tokens as in the source. The judge uses Nemotron Super 3.5 VL instead of GPT-4o; therefore results are a judge-substitution variant, not an exact published-model replication. BERTScore and three-shot conditions are not implemented. Native Responses transport does not request the creator's JSON-object mode or seed; malformed judge output fails visibly.

Clone the source repository and configure `ctbench.resources_servers.ctbench.creator_root` with its absolute path and `judge_model_server: {type: responses_api_models, name: judge_model}`. Preparation uses `CAMPAIGN_SAMPLE_JSONL` and `python benchmarks/ctbench/prepare.py`. Dependencies are the normal Gym runtime; upstream code is AST-isolated to its five deterministic functions, without importing OpenAI or credentials. `gym eval run --benchmark ctbench` is the intended native entry point; only server configuration and mocked HTTP verifier transport have been tested locally, not a live rollout.

Raw creator behavior includes division by zero when no candidate features are extracted. This is retained as a grading error, not silently assigned a score. An additional integrity guard rejects judge outputs that hallucinate, duplicate, or omit input features. The creator scorer itself merely counts returned list lengths. This guard is a documented deviation; retain judge receipts for later raw replay. A nonempty incorrect candidate gives F1 0; exact matching lists give F1 1. Empty output remains a scorer failure.

No data or credentials are committed. License metadata is CC0-1.0. The integration remains unverified until live judge controls and sampled rollouts pass.

Guarded judging requires the native persisted `verification_id`. Each feature-matching call binds the exact creator source bytes, adapter/scorer source hashes and judge generation settings. Missing identity fails before dispatch and retains task metadata in the judge-failure record. Configure `judge_model` separately from the solver policy model, using the authorized Nemotron model; the adapter does not silently select the solver server.
