# Preserve peers when an upstream request fails

Append `--config configs/eval/rate_limit_peer_safe.yaml` to an existing evaluation configuration using `policy_model/openai_model`. Set `GYM_PROVIDER_COOLDOWN_DIRECTORY` to a private, writable directory on the host and `GYM_PROVIDER_COOLDOWN_NAMESPACE` to a non-secret identifier for the **actual shared quota group**. Processes using the same endpoint/model and quota should share these values. The implementation rejects endpoint/model scope mismatches. This is host-local coordination, not distributed quota enforcement or evidence of a per-IP allowance.

The overlay records failed `/run` requests in the existing failure sidecar without inventing a reward or cancelling unrelated in-flight peers. Read the attempted/failed/unresolved denominators alongside scored results. It sets both retry layers to one attempt: a rejected request is not resent. An observed429 publishes Retry-After, or a60-second fallback if that header is unavailable/invalid. Queued model calls wait outside the upstream concurrency slot. Successful budget-exhausted responses keep their original grading and failure classification. Unknown dispatches still block restore/replay.

Keep the benchmark's provider timeout, generation limits, collector dispatch/drain budgets and absolute outer supervisor bound unchanged. Cooldown waiting is **outside** the per-provider-attempt timeout. Already admitted rows can therefore wait past the collector's admission cutoff; they remain bounded by the existing absolute supervisor. New rows are checked against the unchanged collector budget when acquiring a slot and are recorded as undispatched when drained. Do not describe the provider timeout as covering all queue wait. Review queue timing, sidecars and drained counts; if repeated throttling uses the admission window, stop and reconcile instead of increasing budgets silently.

The motivating retained response identified provider priority-based **token** throttling, not an established per-IP request limit. The historical unknown request remains unknown; enabling this overlay does not make it safe to retry. Model-specific fallback tuning requires explicit operational review. This overlay leaves scientific budgets and concurrency untouched.

Validation uses the actual collector, actual model cooldown and local HTTP provider/run boundaries: a rejected request is an infrastructure failure without score, an accepted peer finishes, queued calls wait, budget-zero is retained, and drained rows are not dispatched. A separate real CaptureStore control preserves unknown-state restore refusal. These are component-composition controls, not full native CLI/capture-middleware certification.
